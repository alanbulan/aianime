# v1.1.17

## User-facing Highlights (zh)

- **来源提交**: 本版本由 Gitee Go 根据提交 `a058411904dcc70377d625f7951f6aff3b1d1162` 自动生成，流水线构建编号为 `16`。
- **变更摘要**: fix(desktop): 修复小说导入原生依赖与 Windows 编码异常 问题原因：Cognee 1.0.5 使用 Ladybug 图数据库时，通过 importlib 动态加载 ladybug._lbug 与 ladybug._lbug_capi。原 PyInstaller 配置只收集项目、LiteLLM、Whisper 和 tiktoken 扩展，导致安装版快速导入在图谱初始化阶段报 No module named 'ladybug._lbug_capi'。角色构建捕获该异常后输出包含警告符号的日志，而冻结后端仍使用 GBK stdout，进一步触发 UnicodeEncodeError 并掩盖原始错误。 修复内容：在后端 PyInstaller 清单中显式收集 Ladybug 全部子模块及其原生扩展；后端入口启动时将 stdout/stderr 重配置为 UTF-8，并由 Electron 启动环境同步设置 PYTHONIOENCODING/PYTHONUTF8；新增打包后运行时门禁，直接启动 ai-anime-backend 可执行文件、创建 Ladybug 数据库、执行查询并校验中文与警告符号输出。 验证记录：桌面测试 75 项通过，TypeScript 类型检查与 Ruff 通过；源代码运行时在 GBK 环境下通过；重新生成的 PyInstaller 后端已包含 _lbug.cp312-win_amd64.pyd，并在显式 GBK 环境中完成 Ladybug 建库、查询及 UTF-8 输出验证。
- **版本同步**: Python 包、Electron 安装器、前端版本兜底、依赖锁文件和 README 已统一更新为 1.1.17。
- **更新提示**: 更新窗口将展示本版本记录；安装完成后请重新启动客户端，使本地后端、Hermes 和 Electron 主进程全部切换到新版本。
