# 1.1.74：模型能力与计费边界修复

## 问题及原因

云端模型改为精细积分计费后，Electron 将 `billingVersion`、`quoteRequired`、
`minimumClientVersion`、`pricingAvailable` 混入本地执行能力请求。Python 的
`/api/v1/model-gateway/internal/capability` 严格 schema 拒绝这些未声明字段，
导致启动同步返回422。这不是模型供应商拒绝调用，也不是软件许可失效。

## 实现

- Electron 仍完整保留云端计费元数据，在模型代理中执行报价确认、预算绑定和定价检查。
- 本地执行能力使用显式字段白名单，发送前深拷贝。Python 不接收计费权限，不放宽
  `extra="forbid"`，不引入按次计价或个人积分不足时转扣租户库存的回退。
- 只有本地后端确认能力更新成功后，才保存用于进程重启恢复的快照。
- 同步错误只报告HTTP状态和安全的schema字段路径，不展示请求、凭据或被拒绝的值。
- Python、Electron、Renderer版本兜底、锁文件和发布说明统一为1.1.74；安装后必须
  重启完整客户端，不单独替换某一端文件。

## 验证

标准桌面测试在明确的Node 22.22.1、锁定pnpm依赖环境下通过；原Mac打包测试的
断言与平台跳过条件均未删除。服务器公开模型目录经现有授权RPC读取得到后，实际
通过Gateway JSON投影、Electron目录解析与能力转换，再交给Python真实路由schema
验证；此验收不激活设备、不生成模型任务、不创建报价和扣款。

共享fixture分别用于Node和Python测试，证明原计费字段会触发422，而执行能力投影
能够成功同步，同时未知权限字段继续被拒绝。CI三平台矩阵新增对应Python合同测试，
避免只验证TypeScript后再次漏检本地执行接口。

本轮还执行Renderer类型检查、模型用量领域及组件测试、前端架构检查、主进程构建、
完整CE前端构建及版本一致性检查。执行日志位于服务器 `/tmp/aianime-finish-*`，
正式发布结果须以对应GitHub Actions运行与云端发布记录为准。
