## 首轮失败与修复

### Apple Silicon 媒体依赖

预编译 FFmpeg 虽然版本和校验和匹配，但其 Mach-O 最低系统为 macOS 26，超过应用
承诺的 macOS 15。原生包兼容性检查正确阻止了出包，没有放宽最低系统门禁。

两种 Mac 架构现共用既有的固定源码构建流程：构建脚本 `v9.0.8`、FFmpeg `9.0.1`，
沿用已登记的源码压缩包校验和；源码构建使用其 macOS 11 基线，最终仍逐个检查实际
Mach-O 架构、最低系统、非系统动态链接、编码器及字幕过滤器。缓存与来源记录按
实际架构区分，不再复用要求 macOS 26 的预编译包。

### Windows 换行合同检查

`commercial-channel-parity.test.mjs` 的源码回调正则只接受 LF，在 Windows 的 CRLF
检出错误的“回调缺失”。修复正则并将真实开发/生产源码同时转换成 LF 和 CRLF 运行
原有断言。第二轮 Windows 已通过该合同检查；业务回调和路由逻辑未改变。

## 风险与处置

- Mac 改为源码编译会增加首次构建耗时；保留原有架构、资源冒烟及签名检查。
- 未完成三端构建时，统一发布任务不会运行，原线上版本继续可用。
- 如果新版本发布后出现问题，应通过 Release Owner 撤回该版本并保留历史构件证据；
  不覆盖已发布版本的同名构件，不修改历史校验和，不手动改写发布数据库。
- 本机为 Linux，不能以本地单元测试代替三平台安装包的实际安装、登录、生成与升级验收。
