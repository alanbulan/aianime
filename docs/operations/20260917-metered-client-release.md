# 精细积分与启动合同修复：三平台发布

## 变更范围

本次继续完成此前尚未发布的 `1.1.73` 候选版本。云端余额的 `assetVersion`、
账户与额度桶的 `refundFrozenUnits` 全部映射到 Electron 和 Renderer 合同；
未知字段和非法整数仍拒绝，保留服务端计算的可消费积分，不使用余额回退绕过冻结。
启动数据校验失败改为独立提示，不再把所有接口异常描述为软件许可缺失。

同时携带候选版本已实现的报价确认、预算、消费账单解释与精确积分展示，不能
单独提交部分引用而漏掉对应新增模块。

## 已执行验证

- 桌面合同与打包脚本测试：`294` 项通过，`4` 项依据宿主平台跳过，无失败。
- 桌面主进程和 Renderer 类型检查通过。
- `release:verify` 检查版本来源一致，候选版本为 `1.1.73`。
- 本机系统 Node 缺少 TypeScript 编译支持；使用现有官方 Node 后通过测试，
  没有删除断言、跳过桌面全套测试或修改依赖锁以规避故障。

## 发布方式

沿用 `.github/workflows/build-desktop.yml` 的标签触发与三平台矩阵：Windows x64、
Intel Mac x64、Apple Silicon Mac arm64。三个构建任务必须全部成功，随后
统一校验制品、签名与清单，并调用既有云端发布脚本。禁止覆盖已发布制品。
发布使用已配置的凭据，不在源码、操作记录或对话中记录任何密钥。

## 现场状态与风险

本记录创建时安装包工作流尚未触发；源代码和本机测试通过不代表原生安装、自动更新
或云端发布完成。后续记录实际提交、工作流运行号与结果。若远程构建失败，旧版本
继续保留；修复后重跑同一来源或递增版本，不修改历史校验和。
