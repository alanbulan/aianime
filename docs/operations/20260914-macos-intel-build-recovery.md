并检查三平台耗时差异。代码存储仍为 Gitee `mingcheng_software/ai-manga-desktop`。

此前没有 GitHub FFmpeg 缓存，每次全新宿主都会重新编译。

由于 Intel 失败，统一发布步骤被跳过，另外两个成功制品没有单独发布到云端。

## 实施内容

- 两种 Mac 标准打包入口使用受限重试：只识别上述 DMG 卸载占用错误，最多追加两次，
  等待 10 秒和 20 秒；重用同一构建中的应用、架构及 Intel 配置，通过
  `electron-builder --prepackaged` 重新制作安装器。不会重新编译 FFmpeg 或 Python。
  应用缺失、签名失败、编译失败、其他磁盘错误及进程被信号终止时立即失败。
- 最终制品继续执行所有既有资源、Mach-O 最低系统、签名、媒体运行时及 Sparkle 检查，
  并增加 `hdiutil verify` 和 `unzip -tq`。持续失败不会放行发布。
- 两种 Mac 将 FFmpeg 构建和校验显示为独立步骤，随后立即保存缓存，因此即使 DMG
  后续失败也保留已验证的结果。只缓存 `ffmpeg`、`ffprobe` 两个二进制；精确缓存键包含
  Runner、架构、最低系统和固定源码构建脚本摘要，不使用模糊恢复键。
- 缓存命中仍执行版本、授权选项、架构、最低系统、动态链接、字幕过滤器及编码器检查。
  首次建立缓存仍需源码构建；后续命中的实际提速要由工作流时间验证，不承诺固定耗时。
- 同步所有版本来源至 `1.1.71`，保留 `1.1.70` 的高清参数和六小时视频等待功能。
  新版本仍需三端共同通过才自动上传并发布到 `https://aianime.mingcw.com`。
