# 桌面框架预算确认与视频链路复核

## 变更原因与范围

用户截图中的消费确认来自 Electron `dialog.showMessageBox`，与当前无边框应用的
Base UI、主题和弹层体系不一致。截图还显示定价倍率的18位无意义尾零。
本次只替换正常模型消费的确认窗口，保持文件系统选择器与无法启动界面时的系统
故障报告职责独立；不改变模型生成参数、服务端价格或积分钱包。

## 实现

- 主进程拥有单一确认队列，界面使用既有 `Dialog`、`Button` 和主题设计令牌。
  展示模型、精确预计预占、最高预算、固定价格版本、规范化倍率和到期倒计时。
- 主进程保留报价身份、参数哈希和最高授权数；渲染层只收到展示数据和一次性请求
  编号。回复只允许当前请求编号加确认/取消，不允许带金额等额外字段。
- IPC复用原有主窗口、主frame鉴权；开发与生产的preload、主进程和界面类型同时更新。
  事件回调不向界面暴露原始Electron事件。UI首次读取与事件乱序时，以递增版本处理。
- 并行任务逐个确认；关闭、Esc、取消、请求中止、过期、窗口重载、渲染进程退出和
  登出均不默认授权。队列最多32项，并有有界超时；销毁时及时清理监听与定时器。
- 登出/路由重置同时使尚未返回的旧报价失效，旧会话不能在新会话里弹出消费确认。
  同一意图仍只取得一次报价和授权，保留既有请求幂等，不偷偷提高预算或更换付费模型。
- 中文、英文、浅色、深色和窄窗口都沿用同一组件；不把裸业务编码和冗长说明塞满弹窗。

## 服务端复核

服务器AI和Worker已运行 `commercial-final-video-repair-20260918-r2`。本次只读核对
容器二进制SHA256与该发布证据一致，并重新执行相关服务、计费和上游适配器测试。
三个PROVIDER_CONTRACT_INVALID的修复是服务端用清理后的新map替换旧map，避免将
平台计费字段归档为上游执行参数。两次早期预占失败发生在个人积分分配之前。

Fast的历史上游任务已经失败，参考图上传为上游HTTP401授权故障，不是正常完成。
其4,100积分仍需另一个有权限的管理员审核现有不收费复核，不绕过两人审批。
本次不重发这些任务、不调用新的付费视频接口、不改余额、渠道或倍率，不将静态
和模拟测试写成实际成片验收。第三方上传授权能否恢复是明确的外部边界。
