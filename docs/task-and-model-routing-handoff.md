# 任务取消与模型调用：服务端交接

核查日期：2026-09-02。本次只修改桌面客户端仓库，未修改、部署云端或 BYOK 上游服务，也未执行真实模型生成、取消调用或退款操作。

## 客户端已经修复的部分

- 每次生成绑定提交回执的 `task_id`；旧任务缓存、旧 SSE 连接和迟到失败事件不再覆盖同一对象的新任务。取消不再作为生成失败弹出提示。
- 任务取消或结束会刷新调用记录和额度。打开的调用记录每 5 秒刷新；详情在执行结束但额度仍待结算时继续刷新，结算完成后停止轮询。
- 补齐“取消处理中”“正在输出”等中文状态；预占额度显示为“预占”，最终实扣、退还和余额未结算时显示“待结算”，不假报已退款。
- 场景正向图默认使用 `IMAGE_GENERATION` 全局路由，反向图使用 `IMAGE_EDIT`；全景图按输入来源选择用途。道具、角色的无模型请求也走全局路由。工作台显式传入的 `cloud:` / `byok:` 选择仍固定到所选模型，工作台保存的选择不再隐式覆盖助手请求。
- 云端和 OpenAI-compatible BYOK 图片请求收到可重试 HTTP 响应时，在同一模型路由内最多尝试 3 次，复用请求内容和同一个 `Idempotency-Key`。不对 401/422 等确定性错误重试；本地取消会中断请求及退避等待。BYOK 无响应的传输故障不自动重放写请求，也不因不确定的图片生成错误跨模型再生成。
- 图片错误提示区分云端、BYOK 和未知来源，不再把所有 502 都归为云端。

以上不等于“终止本地任务已自动取消远端调用”。这部分仍需要下面的调用关联合同。

## 1. 取消任务必须精确取消对应调用

当前链路：本地任务 → 桌面模型代理 → 云端 OpenAI-compatible 图片接口 → 云端 invocation。

现有取消接口是 `POST /api/v1/client/relay/invocations/{invocationId}/cancel`，请求体包含 `reason`。调用记录的手动取消已经使用它。但同步图片响应在等待完成前不向桌面提供 invocation ID，本地任务 ID 与云端调用 ID 也没有可靠映射。客户端不能按模型名、时间或当前列表猜测目标，更不能批量取消同模型的其他任务。

云端定位：

- `backend/apps/gateway/api/internal/domain/relay/openai.go`：图片提交后进入 `waitOpenAIInvocation`。`ctx.Done()` 分支只返回错误，没有等同于调用 `CancelInvocation`。
- `backend/apps/ai/rpc/internal/domain/relay/invocation/service.go`：`CancelInvocation` 对确认可取消且仍持有预占的调用执行 `ReleaseReservation`。
- `backend/apps/ai/rpc/model/relay/invocation/invocation_model.go`：已派发或运行中的调用进入 `CANCEL_REQUESTED`，不能立即当作供应商已停止或额度已退还。

需要服务端交付的最小能力（接口字段及路径待双方确认，不是已实现的新接口）：

1. 利用现有 `Idempotency-Key` 精确关联调用，提供当前用户可鉴权的查询和显式取消能力；也可通过提交阶段立即返回 invocation ID 达到同一目的。必须覆盖用户取消先于 invocation 创建完成的竞态。
2. 显式取消向正在运行的 worker / 供应商任务传播；不支持远端终止的供应商必须返回真实状态，不假报完成取消。父任务只能取消自身关联的子调用，不影响后来对同一对象发起的新请求。
3. 未消费预占额度在确认取消后自动释放；已经消费的调用按真实执行结果结算。重复取消、重复释放、取消与成功并发均需幂等。异常待复核要有服务端对账闭环。
4. 调用详情持续返回执行状态和额度状态。`CANCEL_REQUESTED`、`CANCELLED` 与 `HELD`、`RELEASED`、`COMMITTED` 分别表达执行与结算，不可混为一个成功标志。

不要把所有 HTTP 断开或网关超时都解释成用户取消：临时断线后的同幂等键请求需要找回原调用及结果。显式取消与断线恢复必须区分。服务端合同确定后，客户端才能把本地终止自动接到精确的远端取消目标；目前仅关闭 HTTP 连接不足以保证取消供应商任务。

## 2. BYOK 的 prompt 1000 字符限制

当时报错来自 `Seedream-5.0-lite` 所在的 BYOK 上游，响应为：

```text
HTTP 422
type: string_too_long
loc: [body, prompt]
msg: String should have at most 1000 characters
```

错误中 `127.0.0.1:37825` 是桌面转发地址；路由记录确认实际来源是 BYOK。客户端请求包含完整角色和风格提示，没有施加这个 1000 字符上限。

请负责该 BYOK 适配服务的团队核对 `/v1/images/generations` 和 `/v1/images/edits` 的请求 schema，删除不符合真实模型能力的硬编码限制。若模型确有输入上限，应准确声明并返回可理解的错误；校验应在创建付费调用前完成。客户端不会静默截断提示词，也不会重试同一条确定会失败的 422。

本轮没有再次调用真实上游，不能据此认定服务端现在仍保留这个限制，需服务方确认当前部署。

## 3. 图片重试必须真正幂等

截图中两次图片编辑 502 的路由记录为 BYOK，之前桌面只尝试 1 次。本次补齐了有限重试，但客户端传递同一个请求键不能替代服务端去重。

- 云端及 BYOK 适配服务需按用户/供应商、操作和幂等键识别同一请求；同键同参数复用同一调用、计费与结果，同键不同参数应明确拒绝。
- 网关等待超时后，底层可能还在运行。重试应恢复查询/等待原调用，不能再次生成、再次预占或再次扣费。
- 502/503/504 表示暂时失败或结果未知，不是场景、角色等业务前置资产缺失。服务端错误信息应保留请求标识和准确类别，便于对账。
- 不支持幂等键的 BYOK 服务仍可能重复执行或计费，不能声称客户端重试已保证供应商侧“仅执行一次”。

## 联调验收

| 操作 | 必须验证的结果 |
| --- | --- |
| 预占后、派发前终止任务 | 对应 invocation 自动取消，未消费预占自动释放，无需用户再次点调用记录的取消按钮。 |
| 正在生成时终止 | 状态先如实显示取消处理中；随后由服务端确认取消/执行结果及最终结算。 |
| 取消 A 后立即对同一对象发起 B | 取消、失败和额度操作只针对 A；B 正常出图且不出现 A 的失败提示。 |
| 取消与创建/成功并发，重复点击取消 | 不漏取消、不重复退还、不取消其他请求；已消费记录与实际执行相符。 |
| 网关先返回 502，后恢复 | 同键最多一次底层生成和计费；桌面重试成功后只保留成功结果。 |
| 图片参数 422 或鉴权 401 | 不自动重复生成；校验失败无新增消费，错误来源准确。 |
| 调用已取消但额度暂未结算 | 客户端显示待结算并持续刷新，服务端确认释放后额度自动更新。 |
| 助手不传模型，工作台之前选过另一个模型 | 助手走全局用途优先级；手动显式传入模型时仍调用指定模型。 |
